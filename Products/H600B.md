Solid RGB bulb. **Not a segment device.** Two sockets on a fixture are two BLE peripherals, two auth handshakes, two status polls.

Python for auth + encrypt is in [`Products/H600B`](H600B/) (`crypto.py`, `packets.py`, `cli.py`). `python test_crypto.py` replays a captured e701 / power-off / red frame. `python cli.py paint --rgb ff0000` auths then writes color → power → brightness.

## Transports

| Transport | Works | Note |
|---|---|---|
| Bluetooth LE | yes | session-encrypted after auth |
| Govee LAN API | **no** | no UDP LAN API on this SKU in testing |
| Encryption | **yes** | AES-ECB(16) + RC4(4) after `e701`/`e702` |

ADV name: `GVH600B*`.

## GATT

```
service      00010203-0405-0607-0809-0a0b0c0d1910
control      00010203-0405-0607-0809-0a0b0c0d2b11
notify       00010203-0405-0607-0809-0a0b0c0d2b10
```

GATT **read** of `2b10` is often static `01 02`. Not live state.

## Encryption

PSK used only for auth: `MakingLifeSmarte` (16 bytes; same family as GoveeBTTempLogger).

1. `e701` / `e702` handshake.
2. Session key: AES-ECB on 16 bytes + RC4 on 4.
3. Build a 20-byte **plaintext** frame (byte 19 = XOR of 0..18), then encrypt.
4. Decrypt notifies the same way. Keep reading until the **decrypted** opcode matches the query; leftover auth frames decode as garbage.

Do not send plaintext `33` / `aa` frames after auth. They will not work.

## Commands (plaintext, then encrypt)

Phone order when turning on: **color → power on → brightness**.

| Action | Prefix |
|---|---|
| Power | `33 01 01` / `33 01 00` |
| Brightness | `33 04 LL` (`LL` = 0–100) |
| Solid RGB | `33 05 0d RR GG BB` |

There is **no** `33 05 15` segment paint. Hexa / H6088 masks do nothing useful here.

## Status reads (plaintext, then encrypt)

Subscribe to notify, then query.

| Field | Query | Reply |
|---|---|---|
| Power | `aa 01` | `aa 01 {0\|1}` |
| Live brightness % | `aa 04` | `aa 04 {0–100}` |
| RGB | `aa 05` | `aa 05 0d RR GG BB` |
| Version | `aa 06`, `aa 20`, `aa 21` | ASCII |

`aa a5` replies are zeros. This is not a segmented fixture.

`aa 12` is a capability blob, not dim. `33 04 00` is a command that sets brightness to 0.

## Pair of bulbs

Treat each MAC as its own device. A ceiling-fan pair is two connects. Shared "fixture brightness" in a UI is your aggregation (for example max of the two `aa 04` values when either is on).
