Six daisy-chained cubes. Same `33 05 15` opcode family as the [H6061](H6061.md) Hexa, **mask at byte 12** instead of bytes 9–10. Hexa masks do not light these cubes.

Longer write-up: [mpalczew/govee-ble-segments](https://github.com/mpalczew/govee-ble-segments) (`docs/h6088-sconces.md`, `docs/status-read.md`). Probed 2026-08-04 by painting six distinct colors and reading physical order.

## Transports

| Transport | Works | Note |
|---|---|---|
| Bluetooth LE | yes | per-cube color and status below |
| Govee LAN API | whole-device only | segments are BLE |
| Encryption | none | plaintext 20-byte frames |

ADV name: `Govee_H6088_*`.

## GATT

```
service      00010203-0405-0607-0809-0a0b0c0d1910
control      00010203-0405-0607-0809-0a0b0c0d2b11
notify       00010203-0405-0607-0809-0a0b0c0d2b10
```

Subscribe to notify before `aa` queries. Force-quit the Govee phone app; one central only.

## Frame format

20 bytes. Byte 19 = XOR of bytes 0..18.

```
0x33   command
0xaa   status query
```

## Cube numbering

Number along the daisy chain. For a wall map, pick a stable convention (e.g. 1 = left when facing the desk) and stick to it.

| Cube (chain index) | Mask bit (**byte 12**) |
|---:|---|
| 1 | `0x01` |
| 2 | `0x02` |
| 3 | `0x04` |
| 4 | `0x08` |
| 5 | `0x10` |
| 6 | `0x20` |

This is the H6046-style LE bitmask, not the Hexa BE u16.

## Commands (`0x33`)

### Power

```
33 01 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 33   on
33 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 32   off
```

### Global brightness

`33 04 LL` with `LL` = 0–100. Dims the row without changing cube hues. `33 04 00` is dim to 0, not a query.

```
33 04 64 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 53   100%
```

### Cube color

```
33 05 15 01 RR GG BB 00 00 00 00 00 MM 00 00 00 00 00 00 XX
MM = LE segment bit (0x01 … 0x20) at byte index 12
```

Cube 1 red:

```
33 05 15 01 ff 00 00 00 00 00 00 00 01 00 00 00 00 00 00 dc
```

Cube 6 cyan:

```
33 05 15 01 00 ff ff 00 00 00 00 00 20 00 00 00 00 00 00 02
```

### Cube brightness

```
33 05 15 02 LL MM …
```

`LL` at byte 4; mask bit at byte 5.

## Status reads (`0xaa`)

Same path as Hexa: write query, read matching notify.

| Field | Query | Reply |
|---|---|---|
| Power | `aa 01` | `aa 01 {0\|1}` |
| Live row brightness % | `aa 04` | `aa 04 {0–100}` |
| Mode | `aa 05` | `aa 05 15` + zeros after a native multi-cube paint. **Not** live cube RGB. |
| Cube dump | `aa a5 {page}` | see below |

`aa 12` is a capability blob, not dim.

### Cube dump

```
write:  aa a5 NN 00 … XX
reply:  aa a5 NN  {LL RR GG BB}×4  XX
```

- Skip page **0** (zeros on this SKU).
- Pages 1–2 = 6 cubes + pads.
- `LL` is per-cube brightness 0–100. Whole-row dim is `aa 04`.

## Gotchas

- Same opcode as Hexa, different mask byte. Copying `0x0100` / bytes 9–10 will not address cubes.
- One BLE central. Phone app connected ⇒ empty sniffer PCAPs if you missed `CONNECT_IND`, and failed writes from a second central.
- Hold the adapter for the whole 6-write paint. A long scan in the middle leaves the first cubes updated and the rest stale.
- LAN uniform color may not clear a multi-cube BLE paint. Re-paint all six cubes for a solid look.
