Glide Hexa, 10 RGBIC panels. Same GATT family as the [H6088](H6088.md) cubes, but the segment mask sits in a different place. Copying the cube table onto this light will not work.

Captured from the official app with an nRF sniffer (you have to see `CONNECT_IND`, so start sniffing before the phone connects), then rebuilt and painted live. The Govee app is the only central: force-quit it before any of the scripts below will connect.

Check the `Products/H6061` folder for example scripts (`scan.py`, `paint.py`, `status.py`). Edit `DEVICE_NAME` at the top of each file.

## Transports

| Transport | Works | Note |
|---|---|---|
| Bluetooth LE | yes | per-panel color and status below |
| Govee LAN API | whole-device only | discovery / `devStatus` / uniform color. Segments are BLE. |

ADV name looks like `Govee_H6061_*`.

## GATT

```
service      00010203-0405-0607-0809-0a0b0c0d1910
control      00010203-0405-0607-0809-0a0b0c0d2b11
notify       00010203-0405-0607-0809-0a0b0c0d2b10
```

Write the control characteristic **without a response**. Subscribe to notify before sending `aa` queries. A GATT read of either characteristic is not live state (`2b10` is often empty).

## Frame format

20 bytes: identifier, payload, zero-padded, XOR of the first 19 bytes as the last byte. Same shape as [H6127](H6127.md).

```
0x33   command
0xaa   status query (matching opcode comes back on notify)
```

`0xaa 01` on this device is a **power query**, not the keep-alive some older writeups call it. `33 04 00` is dim-to-zero, not a poll.

## Panel numbering

1 is the power injector (cable end), then along the physical snake to 10. The app does not label these.

Color mask is a u16 big-endian at bytes 9–10.

| Panel | Mask (bytes 9–10) |
|---:|---|
| 1 | `0x0100` |
| 2 | `0x0200` |
| 3 | `0x0400` |
| 4 | `0x0800` |
| 5 | `0x1000` |
| 6 | `0x2000` |
| 7 | `0x4000` |
| 8 | `0x8000` |
| 9 | `0x0001` |
| 10 | `0x0002` |

## Commands

### Power

```
3301010000000000000000000000000000000033   on
3301000000000000000000000000000000000032   off
```

### Global brightness

This model is 0–100 (`0x00`–`0x64`), same as [H6004](H6004.md), not 0–255. Dims the wall without changing segment hues.

```
3304640000000000000000000000000000000053   100%
33040a000000000000000000000000000000003d   10%
```

### Segment color

```
33 05 15 01 RR GG BB 00 00 MH ML 00 00 00 00 00 00 00 00 XX
mask = (MH << 8) | ML
```

```
33051501ff0000000001000000000000000000dc   panel 1 red
3305150100ffff00000002000000000000000020   panel 10 cyan
```

### Segment brightness

```
33 05 15 02 LL MH ML …
```

`LL` is 0–100. Mask is at bytes 5–6 (same bits as color). Independent of `33 04`. If the wall still looks dim at LAN 100%, leftover per-segment levels are why.

Do not send `33 04 64` on every reconnect. That flashes the wall mid-scene. Power on, paint segments, then set wall dim once.

## Reading current values

Write `aa {cmd}` on the control char. The matching `aa {cmd}` notify is the reply. Keep reading until the opcode matches.

| Field | Query | Reply |
|---|---|---|
| Power | `aa 01` | `aa 01 {0\|1}` |
| Live wall brightness % | `aa 04` | `aa 04 {0–100}` |
| Mode | `aa 05` | `aa 05 15` + zeros after a multi-seg paint. Not live panel RGB. |
| Segment dump | `aa a5 {page}` | four `LL RR GG BB` slots |
| Version | `aa 06`, `aa 20`, `aa 21` | ASCII |

`aa 12` is a capability blob (often `ff 64 …`), not dim.

### Segment dump

```
write  aaa5NN000000000000000000000000000000XX
reply  aaa5NN {LL RR GG BB}×4 XX
NN = 01, 02, 03
```

Skip page 0 (aliases page 1 here). Pages 1–3 are 10 panels plus two zero pads, power-first order. `LL` is per-segment brightness; whole-wall dim is the separate `aa 04` value.

Mint wall, all `LL=100`:

```
aaa5016400ffae6400ffb76421ff976440ffaf4e
aaa50264a1ffe064a1ffe06440ffaf6421ff9754
aaa5036400ffb76400ffae000000000000000015
```

After a multi-color BLE paint, LAN `colorwc` may not overwrite every panel. Paint all 10 segments for a solid look.
